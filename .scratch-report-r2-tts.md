# R2 TTS — capability-aware dialogue voice degradation

**Branch**: `feat/r2-tts-degrade`  
**Worktree**: `SupaLuv/.worktrees/r2-tts`  
**Date**: 2026-07-17  
**Product decision**: free-form dialogue TTS stays **off** (cost + review surface); client must **not** 400-spam synthesize. Settings fixed-phrase preview remains available.

## What changed

### 1. Server — `/health` TTS capability block

`ttsHealthSnapshot()` now returns:

```json
{
  "providers": { "elevenlabs": boolean, "minimax": boolean },
  "freeformEnabled": boolean,
  "defaultLang": "zh-CN",
  "routingCatalog": "supaluv-core-v1",
  "mixedLanguageMode": "segmented-catalog-required"
}
```

- `freeformEnabled` reads `SUPALUV_TTS_ALLOW_FREEFORM === "1"` via `isTtsFreeformEnabled()`.
- Provider readiness stays under `providers` (from `describeTtsEnv()`); no secrets.
- `/tts/synthesize` free-form gate uses the same helper.

### 2. Client — capability-aware degrade

| Piece | Role |
| --- | --- |
| `apps/web/src/audio/ttsCapability.ts` | Lazy `GET /api/ai/health`, module cache, fail-closed freeform |
| `dialogueVoiceGate.canStartDialogueVoiceRequest` | Requires `freeformEnabled` |
| `dialogueVoiceButtonState` | Disabled + tooltip when freeform off/unknown |
| `useDialogueVoice` | Probe health; **no synthesize** until freeform true; returns UI state |
| `DialoguePanel` | `data-testid="dialogue-voice-button"` when freeform off (disabled + title) |
| i18n | `play.voiceLine` / `play.voiceBudgetCharging` (zh + en, light self-deprecation) |

Settings TTS **preview** (`/tts/preview`, whitelist phrase) is unchanged and stays usable.

### 3. Tests

- `tests/unit/tts-health-freeform.test.ts` — health freeform true/false
- `tests/unit/tts-capability.test.ts` — parse/cache/fail-closed
- `tests/unit/dialogue-voice-freeform.test.ts` — no request plan + button disabled when freeform off
- `tests/unit/dialogue-voice-session.test.ts` — gate freeform field
- `tests/e2e/web-smoke.spec.ts` — mock health freeform=false; assert voice button visible + disabled
