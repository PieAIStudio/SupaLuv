# Design Sparks Log（设计火花记录）

这里记录 owner 与 AI 讨论中碰撞出来、但**尚未实现**的设计想法：谁提的、讨论出了什么、
当前结论是什么。目的是让这些火花在换 session / 换 AI 时不丢失。

规则：

- 每条火花记录"来龙去脉"：owner 原始提议 → 讨论要点 → 当前结论与状态。
- 火花落地后，把该条状态改为 `已落地`，指向实现位置或 ADR，不删除原文。
- 本文件不是规格。落地前需要正式设计时，另开 spec/ADR，并在此回链。

## 2026-07-18：三周目重玩结构（"硬币两面"）

**Owner 提议**：让玩家愿意玩第二、三遍。第一遍看到的不起眼细节（比喻：硬币 A 面），
第二遍串成一条暗线揭露（硬币 B 面）。分层：一周目 = 小说主线 + 人物关系 +
公司（"心动引擎"）以公开面目呈现、逐渐成反派；二周目 = 揭露公司真实运行逻辑、
操控人的原理、内部信息；三周目 = 把 AI 基础知识/常识作为重要内容铺开，含隐藏剧情。

**讨论要点**：

- 这个结构与《尼尔：机械纪元》多周目换视角、《Outer Wilds》"知识即进度"同构，
  是被市场反复验证过的重玩设计；分层（人→公司→AI 原理）情感到机制到知识递进，成立。
- 技术上难度确实不大：Ink 全局变量记周目数 + 条件文本
  `{playthrough >= 2: ...}` 即可让同一场景长出 B 面；路线图可视化新解锁分支。
- **坑一：真正的成本是内容量不是代码**。二周目 B 面≈再写小半本小说。18 章正稿
  未定稿前不为第二遍写正文；但从现在起小说写作执行"双层伏笔纪律"——写 A 面时
  就在 AnvilLocal knowledge 登记每个伏笔的 B 面（哪句台词、哪个道具、哪个背景
  细节将来要翻面）。伏笔写作时埋便宜，事后补贵十倍。
- **坑二（最重要）：第一遍必须独立成立**。一周目单独拿出来是完整的好故事，
  二周目是奖励不是补丁。检验标准：只玩一遍的玩家给不给好评。
- **坑三：三周目"AI 科普"极易变成课本插页**。解法是把知识做成剧情武器：
  想看懂"心动引擎"怎么操控人，就必须搞懂训练数据/对齐/奖励机制——概念是
  解开阴谋的钥匙，不是弹窗小贴士。参照《Papers, Please》：教会玩家极权官僚
  系统，全程没有一页课本。现成素材：大力的霸总语料"盗版言情小说训练的"
  即可讲透"垃圾进垃圾出"。

**状态**：方向已确认值得做。近期可做：周目架构（周目变量 + 存档记周目，约 30
分钟）+ 小说侧伏笔登记纪律。二三周目正文等 18 章定稿后再动。

## 2026-07-18：道具箱/解谜机制 → 证物收集替代

**Owner 提议**：参考其他游戏的道具箱——到特定场景拾取道具，后期解谜解锁。

**讨论要点**：

- 不建议照搬。比喻：在电影院座位上发拼图。冒险游戏的道具解谜是"卡住你"的乐趣；
  互动电影的核心快感是下一句台词、下一个选择，被道具卡住时玩家感到的是憋尿不是
  智力挑战。且需要全新管线（热点标注、道具逻辑、卡死兜底），成本大收益负。
- 但它想满足的需求成立："我在世界里捡到了东西"。用剧情原生方式满足：
  **证物/档案收集**——玩家路过的协议截图、体验官热评、《适配日报》片段自动进
  图鉴（图鉴系统已存在），这些"纸片"正是二周目揭晓的燃料，与三周目结构天然咬合，
  成本近零。

**状态**：道具解谜否决；证物收集待小说定稿后随二周目内容一起排期。

## 2026-07-18：载入小游戏 → AI 等待间隙内容

**Owner 提议**：载入停顿时放讲解图片/背景设定/迷言几句，或极简小游戏（打砖块类）。

**讨论要点**：

- "载入小游戏"是光盘机时代产物（南梦宫曾持有专利至 2015 年）；本作是 Web 游戏，
  真实载入 <2 秒，没有停顿可填。
- 但游戏里存在真正的等待：**AI 生成的 10-15 秒**（AI 支线"灵感生成中…"、将来的
  AI 终章）。这是放"世界观迷言/角色语录/伪产品广告"（如"心动引擎"荒诞用户条款
  轮播）的正确位置。成本低、极提气质。
- 剧情内小游戏（情绪校准、扫码连扫）已存在，路线正确，按章节继续铺。

**状态**：AI 等待间隙的世界观轮播值得做，未排期；打砖块类外挂小游戏否决。

## 2026-07-18：Creator Studio 升格为第二产品线

**Owner 提议**：Creator Studio 是核心，游戏发布后它本身是独立产品，可能收费；
要求 AI 从全局思考架构、画流程图、打界面草稿，再分期实施。

**讨论要点**：仓库里"小说→可玩"的完整 AI 管线已存在但散落成脚本；Studio 的
本质是给管线装人类驾驶舱；铁律是"编辑器不是第二个真相源、人与 AI 走同一 API、
内容包保持引擎可迁移"。市面无 AI-native 等价物（Inky 只编辑文本，
Twine/Tuesday.js 编辑器引擎绑死，Naninovel 收费限 Unity）。

**状态**：已落地为 `SPEC-0004`（全局架构+P0/P1/P2 分期+界面草案），按分期实施。

## 2026-07-18：预生成配音（游客可听、不耗运行时 AI）

**Owner 提议**：既定脚本的配音应预先生成存为静态资源；游客听预生成，只有
AI 现生成的新内容才实时合成计费。

**讨论要点**：判断完全正确，一次性离线成本换零运行时成本。实现关键是离线工具
必须复刻运行时的文本切块（trim + `\n\n` 连接到选择点）与分段路由，key 用
角色+语言+归一化文本哈希；未命中自动回退实时 TTS，优雅降级。已实现于
`tools/voice-pregen/` + `apps/web/src/audio/pregenVoice.ts`。

**状态**：已落地（三章全量语音库入库）。后续规模化时语音库应迁对象存储，
不再进 git。

## 2026-07-18：其他候选机制（讨论中给出，未逐条决策）

- **限时选择**：压力感，Ink 里便宜，值得试一处。
- **台词回响**：前面随口选的话后面被角色记住并引用（"记仇时长"梗的机制化），
  Ink flag 即可。
- 章末结算报告、成就隐藏条目：已有雏形，按现有路线走。
- 不适配本作的物种器官：战斗、合成、体力值、抽卡。

**状态**：候选池，落地前逐条过"是否服务黑色幽默叙事"这一关。
